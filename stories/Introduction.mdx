# Mui theme

Theme, layout, form inputs and data table for React apps, built on [Material UI](https://mui.com/material-ui/) 9 and [Formik](https://formik.org/). Version 3.x is ESM only and expects the consumer to install the UI libraries it builds on (see Get Started).

<div className='subheading'>Get Started</div>

- Point the `@j-meira` scope at GitHub Packages. Create a `.npmrc` in the project (the token is a GitHub personal access token with the `read:packages` scope, kept in an environment variable):

//npm.pkg.github.com/:_authToken=\${NPM_TOKEN}`}

<div className='subheading'>Migrate to v3</div>

3.0 keeps every public export from 2.x. What changes is how the package is packaged and delivered, plus a few component behaviours. Projects still on 1.x go through the v2 guide below first.

### 1. Peer dependencies

Material UI, the date pickers, Emotion, Formik, notistack, dayjs and react-icons are no longer bundled. Install them next to the theme (one copy each, so the theme and the app share the same context):

```bash
pnpm add @j-meira/mui-theme@^3.0.0 \
  @mui/material@^9.0.0 @mui/x-date-pickers@^9.0.0 \
  @emotion/react@^11.14.0 @emotion/styled@^11.14.0 \
  formik@^2.4.0 notistack@^3.0.0 dayjs@^1.11.0 react-icons@^5.0.0
```

Check that exactly one `@mui/material` resolves: `pnpm why @mui/material`.

### 2. Material UI 9 and pickers 9 in your own code

```bash
npx @mui/codemod@latest deprecations/all src
npx @mui/x-codemod@latest v9.0.0/pickers/preset-safe src
```

Then fix what the codemods leave: system props on `Box`, `Grid`, `Stack`, `Typography` and `Link` become `sx`; `InputProps` / `inputProps` become `slotProps.input` / `slotProps.htmlInput`; Autocomplete `renderTags` becomes `renderValue`; `Grid direction='column'` becomes `Stack`.

### 3. ESM only

The CommonJS build and the `require` export condition are gone. Vite projects need nothing. Jest projects add `transformIgnorePatterns` for `@j-meira/mui-theme` or move to Vitest. Next.js adds the package to `transpilePackages`.

### 4. No deep imports

`@j-meira/mui-theme/dist/...` and `.../src/...` are blocked by the `exports` map. Import from the package root, or `@j-meira/mui-theme/scss/*` for styles.

### 5. Behaviour changes

- `Input model='currency'` with `localControl` now applies the mask (it only did in Formik mode before); clearing gives an empty string instead of a lone dot.
- `Input model='radioGroup'` in Formik mode stores the selected option value and shows it checked. The previous behaviour stored an array and nothing looked checked.
- `Input model='mask'` honours `readOnly` even when `slotProps` is passed.
- `DatePicker` opens from the calendar button only; clicking the field edits the date sections.
- `Search`, `SearchRequest` and `SearchGeneric` notify `searchChange` / `onSelected` once per real change, including when async options arrive after the value was set.
- `ListMenu` uses a generated id unless `menu.id` is given (it was always `simple-menu`).
- `SideBarItem` with `initialState` starts open even without an `expanded` prop.
- `MultiProvider` applies the stored dark mode on the first render. The `MUI_THEME_DARk` storage key is unchanged.
- `useCookies` writes the expiry as a UTC string; `useDebounce` cancels pending calls on unmount.

### 6. Minimums

Node 22.13+ for the build, `moduleResolution: bundler` (or `node16` / `nodenext`) in tsconfig so the `exports` map is honoured, and the Material UI 9 browsers listed under Requirements.

### Checklist

- [ ] Peer dependencies installed, single `@mui/material` in the tree
- [ ] Codemods run, system props and slot props fixed
- [ ] Jest transform or Vitest in place (if tests render the theme)
- [ ] No deep imports
- [ ] Type-check, tests and production build green
- [ ] Forms with currency, mask, radio group and date pickers checked by hand, in light and dark mode

<div className='subheading'>Migrate to v2 (legacy)</div>

For projects still on 1.x. Version 1.9.x is already on Material UI 7 and is API-identical to 2.0; only projects below 1.9 need this.

### 1. Dependencies

```bash
pnpm add @j-meira/mui-theme@^2.0.2 react@^19.2.0 react-dom@^19.2.0
```

If Material UI packages are listed directly: `@mui/material@^7.3.0`, `@mui/x-date-pickers@^8.0.0`, `@mui/icons-material@^7.3.0`.

### 2. Grid v2

```bash
npx @mui/codemod@latest v7.0.0/grid-props src
```

`Grid2` is now `Grid`; `xs` / `md` / `lg` props become `size`:

```tsx
// before
<Grid item xs={12} md={6}>...</Grid>
// after
<Grid size={{ xs: 12, md: 6 }}>...</Grid>
```

### 3. Pickers v8

```bash
npx @mui/x-codemod@latest v8.0.0/pickers/preset-safe src
```

Remove `enableAccessibleFieldDOMStructure={false}` and generic type parameters on picker components. The theme's own `DatePicker` props are unchanged.

### 4. React 19

Remove non-DOM props that leak onto native elements through `{...rest}` (`action`, `searchChange`, `model`, `grid`). React 19 warns on them.

### Checklist

- [ ] Theme on 2.0.x, React 19, Material UI 7
- [ ] Grid props migrated to `size`
- [ ] Tests and build green
